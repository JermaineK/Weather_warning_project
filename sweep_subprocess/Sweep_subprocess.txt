Sweep / Threshold Search Subprocess
===================================

Directory: sweep_subprocess/

Purpose
-------
This subprocess runs threshold sweeps and post-selection for grid-based alert models.
Use sweep_manager.py as the entry point (direct or via run_pipeline.py).

Viability-first defaults (new pipeline)
- labelled: data/grid_train_gse_panel_targets.parquet
- model   : models/viability_model.pkl
- target/success: y_commit
- lead-col: t_to_storm_min_h (labels = 0<lead<=L per lead)
- Run best-constrained via sweep_manager to emit results/sweeps/viability_best_thresholds.csv.

Core scripts
------------
- sweep_manager.py: dispatcher (run, gate, best-f1, best-constrained, pick; chain recipes).
- sweep_runner.py: baseline grid sweep across thresholds/persistence/neighbors.
- sweep_gate_runner.py: build/relax gate sweeps.
- best_f1.py: simple F1 sweep (legacy).
- find_best_f1_thresholds_constrained.py: constrained F1/Fbeta per lead (use for viability).
- pick_best_from_sweep.py: filter/sort sweep outputs by coverage/recall/precision constraints.

Example (viability thresholds)
  python sweep_subprocess/sweep_manager.py best-constrained \
    --labelled data/grid_train_gse_panel_targets.parquet \
    --model models/viability_model.pkl \
    --target y_commit \
    --success-col y_commit \
    --lead-col t_to_storm_min_h \
    --leads 24 48 72 120 \
    --min-precision 0.3 \
    --max-coverage 0.4 \
    --fbeta 0.5 \
    --normalize-lon "-180..180" \
    --out results/sweeps/viability_best_thresholds.csv

Then feed thresholds_csv into the scoring/alerts stage (thr_col=thr_Fbeta).

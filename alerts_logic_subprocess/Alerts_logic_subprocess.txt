Alerts Logic Subprocess — Mini README
This directory holds all the alert-shaping steps: turning raw model scores + rules into usable alert grids (thresholded, throttled, denoised).
Everything is fronted by:
python alerts_logic_manager.py <tool> [args...]

The manager only chooses the right script and forwards arguments.

Manager usage
Manager script: alerts_logic_manager.py
python alerts_logic_manager.py <tool> [--dry-run] [tool-specific args...]


tool can be any key in the table above (dash/underscore variants accepted).
--dry-run prints the resolved command without executing it.

Examples:
1) Apply quick inline rules
python alerts_logic_manager.py apply-rules \
  --labelled data/grid_labelled.parquet \
  --rules "gka_knee_ratio|>=|1.2; cape|>=|50" \
  --out results/alerts/alerts_rules_demo.csv.gz

2) Mine lead-band rules
python alerts_logic_manager.py leadband-mine \
  --labelled data/grid_labelled.parquet \
  --target pregen \
  --out results/alerts/leadband_rules.csv

3) Base alerts from trained bundle + threshold
python alerts_logic_manager.py apply-thr \
  --labelled data/grid_labelled_FMA_gka.parquet \
  --model models/grid_logit_perlead.pkl \
  --lead-hours 72 \
  --thr 0.08 \
  --out results/alerts/alerts_FMA_lead72_thr0.08.parquet

4) Throttle by percentile
python alerts_logic_manager.py throttle \
  --alerts results/alerts/alerts_FMA_lead72_thr0.08.parquet \
  --keep-quantile 0.90 \
  --group-by-hour \
  --out results/alerts/alerts_FMA_lead72_thr0.08_thr90.csv.gz

5) Denoise to produce final flags
python alerts_logic_manager.py denoise \
  --alerts results/alerts/alerts_FMA_lead72_thr0.08_thr90.csv.gz \
  --flag-col alert_throttled \
  --persist-hours 3 \
  --min-neighbors 3 \
  --out results/alerts/alerts_FMA_lead72_final.csv.gz

In the full pipeline, the rough flow is:

model bundle → apply-thresholds → throttle → denoise → eval + reports

and the rule-miners / phase tools sit beside that flow as structure-hunters and diagnostics.
